# Personal Team Alpha release — 31 October 2026

This release publishes the personal Team Alpha photography website and Studio OS to https://teamalpha.photography. It is prepared in an isolated checkout; the development checkout and iOS/SaaS work remain available locally.

## Scope and configuration

- Retains the latest personal Studio OS workflows, mobile layouts, client smart links, settings and the restored outline icons.
- Commercial signup, product marketing, invitations, workspace subscriptions and Razorpay billing are disabled in the production build. SaaS support modules required by shared operations remain dormant.
- Native app projects, the disposable sample server, public iOS-preview assets, private environment files, dependencies and generated builds are excluded from this release.
- Frontend: VITE_API_URL=https://team-alpha-api.onrender.com; VITE_SITE_ORIGIN and WEBSITE_PUBLIC_ORIGIN=https://teamalpha.photography; VITE_STUDIO_SAAS_ENABLED=false.
- Backend: FRONTEND_URL=https://teamalpha.photography; SAAS_ENABLED=false; SAAS_SIGNUP_ENABLED=false. CORS explicitly allows the existing frontend service origin and the custom domain.
- Existing MongoDB, JWT, vault, enquiry webhook and Google secrets are preserved. No credential rotation or database restoration is part of the release.
- Gmail, SMTP, Cloudinary and other optional integrations still depend on their existing private configuration and consent; code publication does not activate an unconfigured provider.

## Validation

- 201 frontend tests passed.
- 360 backend tests passed.
- Studio, public-site and mobile ESLint checks passed using the exact package-script arguments.
- Production frontend build passed using the real backend and website origins.
- Build contains no iOS preview assets, disposable sample login or commercial signup interface.
- git diff --check passed.
- Browser preview and prior physical-device checks do not constitute live end-to-end validation. Deployment health, custom-domain responses and authentication routing must be verified after deployment.

## Hosting and rollback

Both services use release/team-alpha-production. The release is delivered through a pull request, with backend deployment first and frontend deployment second.
